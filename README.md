# PasteHatch

Лёгкая Windows-утилита, которая собирает временный контекст для локальных AI-агентов: файлы,
скриншоты, текст и ссылки раскладываются по «корзинам» — обычным папкам на диске. Без серверов,
без облака, без диалогов сохранения.

Интерфейс — стандартное Windows-приложение на WinUI 3: системный заголовок окна, стандартные
`TabView`, `CommandBar`, `ListView`, `TextBox`, `InfoBar`, окно настроек; тема следует системной.

## Что умеет

- **Корзины контекста** — каждая вкладка это папка `%LOCALAPPDATA%\PasteHatch\Baskets\<UID>`;
  путь можно посмотреть в строке состояния и скопировать кнопкой на панели команд.
- **До 10 открытых вкладок** — щелчок переключает, двойной щелчок переименовывает; после
  перезапуска открытые корзины, их названия и содержимое восстанавливаются.
- **Универсальная вставка** — `Ctrl+V` или кнопка «Вставить» на панели команд: скриншот
  сохраняется как `.png`, текст как `.txt`, ссылка как `.url`, файлы из Проводника копируются
  в корзину.
- **Drag & Drop** — файлы можно перетащить в окно.
- **Материалы** — щелчок выделяет, двойной щелчок открывает в приложении Windows по умолчанию,
  `F2` или контекстное меню переименовывают без изменения расширения, `Delete` удаляет после
  подтверждения в Корзину Windows.
- **Быстрая заметка** — `Enter` в поле заметки сохраняет `.txt` с именем по дню недели и времени
  (например `Пн, 13-02.txt`), без диалога сохранения. Двоеточие в имени файла Windows
  использовать нельзя, поэтому в именах файлов оно заменяется дефисом; имя вкладки при этом
  остаётся `Пн, 13:02`.
- **Настройки** — отдельное окно: запускать ли приложение свёрнутым в трей, запоминать ли
  положение окна, держать ли окно поверх других. Изменения применяются сразу.
- **Трей** — приложение работает в области уведомлений: обычный запуск окно не показывает,
  щелчок по значку показывает/скрывает окно, правый щелчок открывает меню «Показать окно»,
  «Настройки», «Выход». Закрытие окна прячет его в трей, повторный запуск показывает уже
  работающее окно, а не создаёт второй экземпляр. Первый запуск (когда ещё нет данных) окно
  открывает, чтобы пользователь нашёл приложение.
- **Нативное поведение** — стандартные контролы, контекстное меню, TaskDialog-подтверждения и
  Корзина Windows; спорные решения принимались по официальным рекомендациям Microsoft
  (см. [`docs/decisions.md`](docs/decisions.md)).

## Требования

- Windows 10 версии 1809+ или Windows 11 (проверено на Windows 11, сборка 26200).
- [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0) — для сборки и запуска из
  исходников. Windows App SDK и WinUI 3 поставляются вместе с приложением
  (`WindowsAppSDKSelfContained`), отдельно устанавливать не нужно.

## Сборка и запуск

```powershell
dotnet build src\PasteHatch.App\PasteHatch.App.csproj -c Release -p:Platform=x64
.\src\PasteHatch.App\bin\x64\Release\net9.0-windows10.0.19041.0\win-x64\PasteHatch.exe
```

Либо готовые скрипты:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1   # Release-сборка, печатает путь к exe
powershell -ExecutionPolicy Bypass -File scripts\run.ps1     # сборка при необходимости и запуск
```

Аргумент `--show` открывает окно сразу, не дожидаясь щелчка по значку в трее.
Архитектура — x64 (при необходимости можно собрать `-p:Platform=ARM64`).

### Ярлык на рабочем столе

Сборка по умолчанию — framework-dependent: приложение занимает папку `bin\Release`, но требует
установленного **.NET 9 Desktop Runtime** (входит в SDK). Ярлык на рабочем столе создаётся так:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1                 # если ещё не собрано
powershell -ExecutionPolicy Bypass -File scripts\install-shortcut.ps1      # ярлык PasteHatch на рабочем столе
powershell -ExecutionPolicy Bypass -File scripts\install-shortcut.ps1 -Uninstall   # убрать ярлык
```

Ярлык указывает на `src\PasteHatch.App\bin\x64\Release\...\PasteHatch.exe`; после пересборки
цель не меняется.

## Где хранятся данные

| Что | Где |
| --- | --- |
| Материалы корзин | `%LOCALAPPDATA%\PasteHatch\Baskets\<UID>\` |
| Открытые вкладки, их названия, активная вкладка, геометрия окна | `%LOCALAPPDATA%\PasteHatch\state.json` |
| Настройки приложения | `%LOCALAPPDATA%\PasteHatch\settings.json` |
| Корзина удалённых материалов | стандартная Корзина Windows (файлы можно восстановить) |

Папка корзины названа коротким UID (6 символов без похожих `I/O/0/1`); отображаемое имя вкладки
хранится отдельно от имени папки. Файлы на диске — источник истины: состояние вкладок
восстанавливается и по `state.json`, и по папкам в `Baskets`, поэтому потеря файла состояния не
теряет материалы.

Для автотестов приложение поддерживает переопределение пути данных: `PASTEHATCH_DATA_ROOT`
(в обычной работе не задаётся).

## Горячие клавиши и жесты

| Действие | Как |
| --- | --- |
| Добавить содержимое буфера | `Ctrl+V` при фокусе в окне или кнопка «Вставить» |
| Добавить файлы | перетащить в окно |
| Выбрать материал | щелчок |
| Открыть материал | двойной щелчок (или `Enter` на выбранном) |
| Переименовать материал | `F2` или контекстное меню |
| Контекстное меню материала | правый щелчок, `Shift+F10` или клавиша меню |
| Удалить материал | `Delete` (с подтверждением) |
| Переименовать вкладку | двойной щелчок по вкладке, `Enter` — сохранить, `Esc` — отменить |
| Создать/закрыть корзину | `+` в строке вкладок / `×` на вкладке (с подтверждением) |
| Показать/скрыть окно | щелчок по значку в трее |
| Свернуть в трей | закрыть окно (`×` заголовка) или `Alt+F4` |
| Настройки | кнопка «Настройки» на панели команд или правая кнопка по значку в трее |
| Выйти совсем | меню трея «Выход» |

## Тесты

Юнит-тесты ядра (именование, классификация, состояние, корзины, коллизии имён, восстановление):

```powershell
dotnet test tests\PasteHatch.Core.Tests\PasteHatch.Core.Tests.csproj
```

Базовый smoke-тест (проверяет только essentials: запуск, создание корзины и state, окно,
добавление текста через кнопку «Вставить», единственный экземпляр). Запускается с окном
за пределами экрана, без активации и без значка в трее, поэтому не мешает работе за компьютером:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\smoke.ps1
```

Осознанно оставлен только базовый smoke: приложение развивается, и хрупкие UI-сценарии
(подтверждения, клавиатурные комбинации, drag & drop) дешевле проверять одноразовым прогоном,
чем поддерживать сложный автоматизированный набор.

## Устройство

```
src/PasteHatch.Core     — домен: корзины, материалы, именование, state.json, настройки
src/PasteHatch.App      — WinUI 3: окно, вкладки, список, заметка, настройки + Platform:
                          трей, буфер, Корзина Windows, TaskDialog, single instance
tests/PasteHatch.Core.Tests — xUnit-тесты домена
scripts                 — сборка/запуск/генерация иконки/базовый smoke-тест
docs                    — бриф, архитектура, принятые решения, прототип
```

Подробнее: [`docs/architecture-overview.md`](docs/architecture-overview.md) и
[`docs/decisions.md`](docs/decisions.md).

## Известные ограничения

- .NET 9 — Standard Term Support: поддержка заканчивается 10.11.2026. Код не использует
  API, привязанных к .NET 9, поэтому переход на .NET 10 LTS — замена целевой платформы
  (`net9.0-windows10.0.19041.0` → `net10.0-windows10.0.19041.0`) после установки SDK 10.
- Папки не принимаются вставкой/перетаскиванием (по брифу поддерживаются файлы); вложенную
  папку нужно открыть и перетащить её файлы.
- Последнюю вкладку нельзя закрыть: приложение всегда работает с хотя бы одной корзиной.
- Список материалов не следит за изменениями папки в реальном времени; обновляется при
  переключении вкладок, добавлении материалов и показе окна из трея.
